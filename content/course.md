## Что поправить перед выдачей материалов

1. Включённые в уроки POM фиксируют Spring Boot `3.2.0`, Docker-примеры — Java 17 и PostgreSQL 15, Security — JJWT `0.12.3`. Это конкретная база старых примеров, а не проверенный выбор версий на сентябрь 2026. Подготовить один согласованный стартовый проект; не предлагать одновременно «последний Boot» и слепое копирование этих POM. Уроки Spring-тестирования используют `@MockBean`; совместимость проверить с выбранным стеком.
2. Автоматическая проверка локальных Markdown-ссылок нашла 18 отсутствующих целей. Особенно важны отсутствующие отдельные уроки SQL про ACID/pooling, отдельный WebMvcTest и `hints.md`/`requirements.md` проекта Task Manager. Указатели из README нельзя считать наличием самого материала. Выше даны существующие файлы.
3. В Security-уроке строка секрета с дефисами предлагается как корректный пример, а код использует обычный `Decoders.BASE64.decode`. Эти форматы не согласованы. Фильтр вызывает парсер токена без обработки ошибки; нужно явно проверить ответы на просроченный и повреждённый токен. В DTO регистрации `@Email` и `@Size` сами по себе не выражают обязательность полей.
4. В первом Testcontainers-классе оба теста создают один email без очистки/отката. При UNIQUE возможен конфликт, без UNIQUE тесты всё равно делят данные. Сам текст позже объясняет очистку, но стартовый фрагмент надо исправить до копирования. `@Transactional` теста также нельзя автоматически считать откатом HTTP-операций, выполняемых сервером в другом потоке.
5. В Compose-примере «полный стек» есть URL Elasticsearch без сервиса Elasticsearch. Dev-конфигурация требует build-target `development`, которого показанные рядом Dockerfile-примеры не определяют. Для ученика подготовить минимальный согласованный Compose.
6. Схемы и запросы в SQL-файлах полезны как тренажёр, но скрипт тестовых данных сначала удаляет учебные таблицы. Запускать в отдельной учебной БД. Приведённое Bash-перенаправление `< test-data.sql` не является готовой командой PowerShell; дать проверенную Windows-команду, например через `psql -f`.

## Что дополнить наставнику

- **Git как ежедневная практика.** В курсе Git указан требованием, но самостоятельного урока branch/commit/diff/PR/review/conflict нет. Каждая небольшая работа Library должна завершаться осмысленным коммитом и коротким объяснением diff; отдельно отработать конфликт и исправление по review.
- **Тесты с первой недели.** Начать с контрактов коллекций и воспроизведения дефектов, затем unit-тесты сервисов, MockMvc и PostgreSQL. Учить различать ошибку реализации, неясное требование и неверный тест. Исходная последовательность откладывает тесты слишком далеко для текущего ученика.
- **SQL и транзакции.** Есть хороший базовый SQL и пример commit/rollback, но полноценного обещанного файла про ACID нет. Добавить две SQL-сессии: две выдачи одного экземпляра, откат, ограничение целостности, уровень изоляции и выбранный способ предотвратить конфликт. Индекс проверять через план запроса, а не универсальное правило «Seq Scan плох».
- **Многопоточность.** Отдельного блока по thread safety, `synchronized`, `volatile`, executor и race condition не найдено. Добавить ограниченный Core-модуль после коллекций и до обсуждения конкурентной выдачи. Показать различие между защитой памяти одного процесса и ограничениями/транзакциями БД.
- **Миграции и запуск.** В курсе есть отдельные уроки миграций, профилей и логирования; включить минимум при первом подключении PostgreSQL, а не ждать завершения Security. Не копировать пример Flyway с двумя файлами версии `V5` как рабочую пару forward/rollback в один каталог миграций.
- **Масштаб работы.** При двух встречах по 60 минут и 5–9 часах самостоятельной работы лучше один проверяемый прирост Library в неделю. На встрече разбирать решение, отлаживать и проверять перенос знаний. Полные калькулятор доставки, блог, магазин и Task Manager параллельно не нужны; их задания можно использовать для одной контрольной задачи на перенос навыка.

Минимальный итог перед переходом к карьерной подготовке: ученик самостоятельно объясняет и исправляет Core, демонстрирует REST Library с PostgreSQL, тестами и README запуска, пишет JOIN/GROUP BY без ORM, защищает свои решения на review. Security, углублённая конкурентность и расширение домена продолжаются по результатам контрольных проверок, а не только по календарю.
