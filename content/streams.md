# Stream API и Optional — пошаговые примеры

Это дополнение к лекции **«14 Функциональное программирование»**. Здесь мы не вводим новую теорию, а медленно, шаг за шагом, разбираем готовые примеры: смотрим, что происходит со стримом после каждой операции, и почему пишем именно так.

Как читать материал:
- Сначала идёт **задача**.
- Потом **разбор по шагам** — конвейер собирается по одной операции, и после каждой видно промежуточное состояние.
- В конце **готовое решение** целиком.

Во всех примерах считаем, что есть такие данные:

```java
record Order(String customer, String city, double amount, List<String> items) {}

List<Order> orders = List.of(
    new Order("Аня",  "Москва",        1500, List.of("книга", "ручка")),
    new Order("Боря", "Питер",          300, List.of("ручка")),
    new Order("Вика", "Москва",        9000, List.of("ноутбук", "мышь", "коврик")),
    new Order("Гена", "Казань",         750, List.of("книга")),
    new Order("Аня",  "Москва",        2200, List.of("монитор", "кабель")),
    new Order("Боря", "Питер",          120, List.of("ручка", "тетрадь"))
);
```

## Часть 1. Stream API

### Пример 1. Базовый конвейер: «крупные» заказы из Москвы

**Задача:** получить имена клиентов из Москвы, у которых сумма заказа больше 1000, в верхнем регистре и по алфавиту.

Разбираемся по шагам. Главная идея: стрим — это «конвейер», и после каждой операции у нас на ленте лежит чуть-чуть другой набор данных.

**Шаг 1. Источник.** Берём стрим из списка. Пока на ленте все 6 заказов.

```java
orders.stream()
// на ленте: все 6 заказов
```

**Шаг 2. Фильтруем по городу.** Оставляем только Москву.

```java
orders.stream()
    .filter(o -> o.city().equals("Москва"))
// на ленте: Аня(1500), Вика(9000), Аня(2200)
```

**Шаг 3. Фильтруем по сумме.** `filter` можно ставить сколько угодно раз.

```java
orders.stream()
    .filter(o -> o.city().equals("Москва"))
    .filter(o -> o.amount() > 1000)
// на ленте: Аня(1500), Вика(9000), Аня(2200) — все прошли
```

**Шаг 4. Преобразуем заказ в имя.** `map` меняет тип элемента: был `Order`, стал `String`.

```java
    .map(Order::customer)
// на ленте: "Аня", "Вика", "Аня"
```

**Шаг 5. Верхний регистр и уникальность.** «Аня» встречается дважды — уберём дубликат.

```java
    .map(String::toUpperCase)
    .distinct()
// на ленте: "АНЯ", "ВИКА"
```

**Шаг 6. Сортировка и сбор результата.** `sorted()` сортирует по алфавиту, `toList()` — терминальная операция, запускает весь конвейер.

```java
    .sorted()
    .toList();
// результат: ["АНЯ", "ВИКА"]
```

**Готовое решение:**

```java
List<String> result = orders.stream()
    .filter(o -> o.city().equals("Москва"))
    .filter(o -> o.amount() > 1000)
    .map(Order::customer)
    .map(String::toUpperCase)
    .distinct()
    .sorted()
    .toList();

System.out.println(result);  // [АНЯ, ВИКА]
```

Обрати внимание: читается почти как обычное предложение — «возьми заказы, оставь московские, оставь крупные, возьми имена, в верхний регистр, убери повторы, отсортируй».

### Пример 2. Сумма: сколько всего денег принесли заказы

**Задача:** посчитать общую сумму всех заказов.

Когда нужно из чисел получить одно число, удобно перейти на специальный «числовой» стрим — `IntStream` / `DoubleStream`. У них есть готовые `sum()`, `average()`, `max()`.

**Шаг 1. Превращаем заказы в числа.** `mapToDouble` отдаёт `DoubleStream`.

```java
orders.stream()
    .mapToDouble(Order::amount)
// на ленте: 1500.0, 300.0, 9000.0, 750.0, 2200.0, 120.0
```

**Шаг 2. Суммируем.** У числового стрима `sum()` уже встроен.

```java
double total = orders.stream()
    .mapToDouble(Order::amount)
    .sum();

System.out.println(total);  // 13870.0
```

> Без `mapToDouble` пришлось бы писать `reduce(0.0, Double::sum)` — тоже рабочий вариант, но через числовой стрим короче и понятнее.

### Пример 3. collect в Map: клиент → его суммарные траты

**Задача:** получить `Map<String, Double>`, где ключ — имя клиента, значение — сумма всех его заказов.

Здесь один клиент встречается несколько раз (Аня, Боря), поэтому нужен `groupingBy` с «дозбором» значений.

**Шаг 1. Группируем по клиенту.** Если просто сгруппировать, получим `Map<String, List<Order>>`.

```java
orders.stream()
    .collect(Collectors.groupingBy(Order::customer))
// {Аня=[Order(1500), Order(2200)], Боря=[...], Вика=[...], Гена=[...]}
```

**Шаг 2. Вместо списка заказов — сумма.** Второй аргумент `groupingBy` говорит, что делать с каждой группой. `summingDouble` складывает поле `amount`.

```java
Map<String, Double> byCustomer = orders.stream()
    .collect(Collectors.groupingBy(
        Order::customer,            // ключ — имя
        Collectors.summingDouble(Order::amount)  // значение — сумма
    ));

System.out.println(byCustomer);
// {Аня=3700.0, Боря=420.0, Вика=9000.0, Гена=750.0}
```

`groupingBy` + второй коллектор (`summingDouble`, `counting`, `mapping`, ...) — это очень частый приём. Запомни его как «сгруппируй по X, а внутри посчитай Y».

### Пример 4. groupingBy + counting: сколько заказов в каждом городе

**Задача:** получить `Map<String, Long>` — город и количество заказов в нём.

Это тот же приём, что и в примере 3, только внутри группы считаем не сумму, а количество.

```java
Map<String, Long> ordersPerCity = orders.stream()
    .collect(Collectors.groupingBy(
        Order::city,
        Collectors.counting()
    ));

System.out.println(ordersPerCity);
// {Москва=3, Питер=2, Казань=1}
```

> Этот пример очень близок к задаче «подсчёт частоты слов» из лекции. Разница только в том, что там сначала текст надо разбить на слова. Принцип — тот же.

### Пример 5. flatMap: все товары из всех заказов

**Задача:** собрать единый список всех товаров (поле `items`) из всех заказов, без повторов, по алфавиту.

Проблема: у каждого заказа `items` — это `List<String>`. Если просто сделать `map(Order::items)`, на ленте окажутся **списки внутри стрима**, а нам нужны отдельные товары. `flatMap` «расплющивает» вложенные стримы в один.

**Шаг 1. Что даёт обычный map.** Тип получается неудобный — стрим списков.

```java
orders.stream()
    .map(Order::items)
// на ленте: ["книга","ручка"], ["ручка"], ["ноутбук","мышь","коврик"], ["книга"], ...
// тип: Stream<List<String>>  — не то, что нужно
```

**Шаг 2. Меняем map на flatMap.** Каждый список превращаем в стрим (`List::stream`), и flatMap склеивает их в один поток.

```java
orders.stream()
    .flatMap(o -> o.items().stream())
// на ленте: "книга","ручка","ручка","ноутбук","мышь","коврик","книга","ручка","тетрадь"
// тип: Stream<String>
```

**Шаг 3. Убираем повторы и сортируем.**

```java
List<String> allItems = orders.stream()
    .flatMap(o -> o.items().stream())
    .distinct()
    .sorted()
    .toList();

System.out.println(allItems);
// [кабель, книга, коврик, монитор, мышь, ноутбук, ручка, тетрадь]
```

Правило простое: **«элемент → коллекция/стрим» — это flatMap, а не map.**

### Пример 6. Топ-N: три самых дорогих заказа

**Задача:** найти 3 заказа с самой большой суммой.

Здесь связка `sorted(Comparator...)` + `limit(n)`.

**Шаг 1. Сортируем по сумме.** По умолчанию сортировка по возрастанию, нам нужно наоборот — `reversed()`.

```java
orders.stream()
    .sorted(Comparator.comparingDouble(Order::amount).reversed())
// на ленте: 9000, 2200, 1500, 750, 300, 120
```

**Шаг 2. Берём первые три.** `limit(3)` обрезает ленту.

```java
    .limit(3)
// на ленте: 9000, 2200, 1500
```

**Шаг 3. Достаём имена (или оставляем заказы).**

```java
List<String> top3 = orders.stream()
    .sorted(Comparator.comparingDouble(Order::amount).reversed())
    .limit(3)
    .map(o -> o.customer() + " (" + o.amount() + ")")
    .toList();

System.out.println(top3);
// [Вика (9000.0), Аня (2200.0), Аня (1500.0)]
```

> Приём `sorted(...).limit(n)` — основа любой задачи вида «топ-N». Дальше уже неважно, что внутри: числа, слова, объекты.

### Пример 7. Статистика одной операцией

**Задача:** получить сразу min, max, среднее и сумму по суммам заказов.

Для числовых стримов есть готовый объект статистики — не нужно считать каждую метрику отдельно.

```java
DoubleSummaryStatistics stats = orders.stream()
    .mapToDouble(Order::amount)
    .summaryStatistics();

System.out.println("Количество: " + stats.getCount());   // 6
System.out.println("Сумма:      " + stats.getSum());      // 13870.0
System.out.println("Минимум:    " + stats.getMin());      // 120.0
System.out.println("Максимум:   " + stats.getMax());      // 9000.0
System.out.println("Среднее:    " + stats.getAverage());  // 2311.66...
```

Один проход по данным — и все цифры сразу. Это удобная альтернатива тому, чтобы делать `.sum()`, `.average()`, `.max()` по отдельности.

## Часть 2. Optional

`Optional<T>` — это «коробка», в которой либо лежит значение, либо нет. Главная цель — не получить случайный `NullPointerException` и явно описать ситуацию «значения может не быть».

### Пример 8. Optional как результат поиска

Многие операции стрима, которые «могут ничего не найти», возвращают `Optional` — например `findFirst()`, `max()`, `min()`. Это сигнал: результата может не быть, обработай оба случая.

**Задача:** найти первый заказ дороже 5000 и вывести имя клиента, а если такого нет — написать «не найдено».

**Шаг 1. Ищем — получаем Optional.** `findFirst()` возвращает `Optional<Order>`, а не `Order`.

```java
Optional<Order> found = orders.stream()
    .filter(o -> o.amount() > 5000)
    .findFirst();
// внутри коробки: Order(Вика, 9000)
```

**Шаг 2. Достаём имя безопасно.** `map` работает «внутри коробки»: если значение есть — преобразует, если пусто — остаётся пусто.

```java
Optional<String> name = found.map(Order::customer);
// внутри коробки: "Вика"
```

**Шаг 3. Разворачиваем с запасным вариантом.** `orElse` отдаёт значение или дефолт, если коробка пуста.

```java
String result = orders.stream()
    .filter(o -> o.amount() > 5000)
    .findFirst()
    .map(Order::customer)
    .orElse("не найдено");

System.out.println(result);  // Вика
```

Если поменять порог на `> 50000`, ничего не найдётся, и тогда выведется `не найдено` — без всяких ошибок.

### Пример 9. ofNullable + цепочка map: безопасный доступ к «вложенным» данным

**Задача:** есть метод, который ищет заказ по клиенту (и может вернуть `null`). Нужно получить первый товар из заказа, а если что-то по пути отсутствует — вернуть `"—"`.

```java
Order maybeOrder = findOrderByCustomer("Гена");  // может вернуть null
```

**Шаг 1. Заворачиваем потенциальный null в Optional.** `ofNullable` создаёт пустую коробку, если пришёл `null` (в отличие от `of`, который на `null` упадёт).

```java
Optional.ofNullable(maybeOrder)
// если null → пустая коробка, если объект → коробка с заказом
```

**Шаг 2. Идём по «вложенности» через map.** Каждый `map` срабатывает, только если коробка не пуста.

```java
Optional.ofNullable(maybeOrder)
    .map(Order::items)              // список товаров
    .filter(items -> !items.isEmpty())  // и он не пустой
    .map(items -> items.get(0))     // первый товар
```

**Шаг 3. Запасной вариант.**

```java
String firstItem = Optional.ofNullable(maybeOrder)
    .map(Order::items)
    .filter(items -> !items.isEmpty())
    .map(items -> items.get(0))
    .orElse("—");

System.out.println(firstItem);
```

Сравни с «классикой»:

```java
// Опасный вариант — куча проверок и риск NPE
if (maybeOrder != null && maybeOrder.items() != null && !maybeOrder.items().isEmpty()) {
    return maybeOrder.items().get(0);
}
return "—";
```

Цепочка `Optional` короче и не даёт забыть про `null`.

### Пример 10. orElseGet и orElseThrow — чем отличаются от orElse

Когда коробка пустая, есть три способа реагировать:

```java
Optional<Order> found = orders.stream()
    .filter(o -> o.city().equals("Сочи"))
    .findFirst();   // в нашем списке Сочи нет → пусто
```

**`orElse` — простое значение по умолчанию.** Подходит, когда дефолт уже готов.

```java
Order result = found.orElse(new Order("гость", "—", 0, List.of()));
```

**`orElseGet` — дефолт «по требованию».** Лямбда выполнится, только если коробка пуста. Полезно, когда вычисление дефолта дорогое.

```java
Order result = found.orElseGet(() -> loadDefaultOrder());  // вызовется лишь при отсутствии
```

> Разница тонкая, но важная: в `orElse(...)` аргумент вычисляется **всегда**, даже если значение есть. В `orElseGet(...)` — только при пустой коробке.

**`orElseThrow` — «значения нет — это ошибка».** Когда отсутствие результата недопустимо.

```java
Order result = found.orElseThrow(
    () -> new NoSuchElementException("Заказ из Сочи не найден")
);
```

### Пример 11. ifPresent / ifPresentOrElse — когда нужно действие, а не значение

Иногда нам не нужно доставать значение — нужно просто что-то сделать, если оно есть.

```java
Optional<Order> found = orders.stream()
    .filter(o -> o.amount() > 5000)
    .findFirst();

// только если нашли
found.ifPresent(o -> System.out.println("Нашли крупный заказ: " + o.customer()));

// и для случая «нашли», и для «не нашли»
found.ifPresentOrElse(
    o  -> System.out.println("Есть: " + o.customer()),
    () -> System.out.println("Крупных заказов нет")
);
```

Это аккуратная замена связке `if (opt.isPresent()) { ... } else { ... }`.

## Короткая шпаргалка

**Stream — последовательность шагов:**
- `filter` — отсеять лишнее (тип не меняется)
- `map` — преобразовать каждый элемент (тип может смениться)
- `flatMap` — когда «элемент → коллекция», склеить всё в один поток
- `distinct` / `sorted` / `limit` / `skip` — навести порядок на ленте
- `collect` / `toList` / `count` / `sum` — **терминальные**, запускают конвейер
- `groupingBy(ключ, внутреннийКоллектор)` — сгруппировать и посчитать внутри

**Optional — коробка с значением или без:**
- создать: `of` (точно не null), `ofNullable` (может быть null), `empty`
- преобразовать внутри: `map`, `filter`, `flatMap`
- достать: `orElse` (готовый дефолт), `orElseGet` (дефолт по требованию), `orElseThrow` (ошибка)
- сделать действие: `ifPresent`, `ifPresentOrElse`
- избегай `get()` без проверки
