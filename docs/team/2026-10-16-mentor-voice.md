# Голос наставника: правила для учебных текстов

Статус: утверждено владельцем 16.10.2026. Ревью: `product-analyst`, `ux-designer`.

Решения владельца: домашние работы и ревью прошедших занятий не переписываем; словарь «занятие, а не урок» действует и в учебных текстах; ревизию упражнения поднимаем, только когда по нему нет работы в процессе; интерфейс и `content/` — отдельные задачи; пояснения сверх «было» допустимы, если раскрывают уже сказанное.

Учебный текст должен звучать так, как наставник говорит на занятии: коротко, по делу, на «ты», с примерами из проекта ученика. Без следов генерации.

## Где и как строго

| Текст | Кто читает | Правка |
|---|---|---|
| Задания ученику, материалы, текущая домашняя работа, маршрут | ученик | полная |
| Название, условие и названия тестов упражнения, комментарии в заготовке | ученик | полная, только с новой ревизией упражнения |
| Сценарий, план, эталоны, описание комплекта, заметки тренажёра для наставника | наставник | лёгкая: убрать маркеры, разметку сценария не трогать |
| Домашние работы и ревью прошедших занятий | ученик | по решению владельца: это запись того, что ученик получил |
| Интерфейс | обе роли | отдельная задача по словарю `ux-designer` |
| `content/` прежнего кабинета | — | отдельная задача по решению владельца |

Новые комплекты сразу пишем по этим правилам.

## Как звучит

- К ученику на «ты», одно обращение на весь текст. О себе наставник говорит «я»: «чем я заложил», «я внесу ошибку».
- Короткие фразы с глаголом, как вслух: «Если id уже занят, брось `IllegalStateException`», а не «id занят — `IllegalStateException`».
- Сначала зачем, потом что сделать. Одна мысль на абзац, в абзаце не больше 3–4 предложений.
- Примеры из проекта ученика и из жизни.
- Похвала конкретная: что именно получилось.
- Одно действие называем одним глаголом. Не чередуем «брось», «нужен», «выбрасывается» ради разнообразия.
- Список, когда пункты однородные: шаги, требования, случаи, вопросы, что приложить. Объяснение пишем абзацем.
- «Стало» не длиннее «было» больше чем в полтора раза. Если длиннее, ищем воду.

## Слова

- «Занятие», а не «урок»: в заголовках («# Занятие 1. …», «Домашняя работа после третьего занятия») и в тексте («на занятии»). Номер в заголовке ставим, только если он совпадает с номером занятия в кабинете.
- «Домашняя работа», дальше можно «ДЗ». «Домашку» не пишем.
- Задания (текст ученику), упражнения (тренажёр). Задачи LeetCode остаются задачами.
- Названия разделов и кнопок кабинета пишем точно как в интерфейсе, в «ёлочках»: «Домашняя работа», «Тренажёр», «Ревью».
- На экранах, которые видят обе роли (тренажёр, история сдач, ревью), фраза безличная или выбирается по роли.

## Маркеры, которые убираем

1. Канцелярит и пустые вводные: «важно отметить», «стоит отметить», «таким образом», «давайте рассмотрим», «в данном разделе», «является», «осуществляет», «позволяет», «необходимо», «в рамках», «в качестве».
2. Длинное тире вместо глагола: «Дубль id — исключение». Тире-связка «Класс — это чертёж» допустима, но не больше одной на абзац. Исключения: заголовки частей «01/06 · 0–5 мин — …» и ячейки таблиц.
3. Двоеточие-заголовок в начале абзаца («Почему:», «Итог:») и жирные метки через строку. Исключение: метки сценария наставника «Скажи», «Спроси», «Ожидаем», «Почему», «Если», «Обязательный результат», «До занятия», «После встречи».
4. Жирный через слово. Жирным выделяем не больше одной вещи на раздел.
5. Шаблонные тройки: три прилагательных подряд, три одинаково построенных предложения, «быстро, надёжно и удобно».
6. Риторический вопрос, на который текст тут же отвечает сам: «Зачем граница? Без неё…».
7. Пересказ очевидного: «в этом разделе мы разберём…», первая фраза, повторяющая заголовок, итог, повторяющий сказанное.
8. Оценки и восторги: «отличный», «мощный», «ключевой», «элегантный», «идеальный». Знаки оценки работы в кабинете («отлично», «хорошо» и др.) — системные метки, правило их не касается.
9. Кальки с английского: «имплементировать», «кейс», «в терминах», «делает смысл», «сфокусироваться на».
10. Конспект из пунктов «X — Y» там, где нужно объяснить.
11. Эмодзи и декоративные значки.
12. Дежурные концовки: «Удачи!», «Если остались вопросы, пиши», «Ты справишься!».
13. «Ты» и «вы» вперемешку.

## Что не меняем

- Код, имена классов, методов, полей и исключений, команды, пути, ссылки, номера коммитов.
- Смысл требований: условия, граничные случаи, порядок проверок, допустимые значения, число тестов, ориентиры по времени. Каждое требование из старого текста должно найтись в новом и не стать мягче («должен покраснеть» не превращается в «посмотри, покраснеет ли»).
- Число и порядок разделов «## » в тексте ученика: сценарий открывает «часть N ученика» по порядковому номеру раздела.
- Номера частей «01/06 · …»: на них ссылаются тренажёр и сценарий.
- Таблицы и разметку сценария наставника.
- Факты. Можно пояснить уже названный термин («`double` для дробных»). Можно взять уточнение из ревью или сценария того же комплекта. Новые требования и утверждения не добавляем.

## Ограничения формата

Тексты рендерят три разных движка: задания и сценарий занятия — клиент (markdown-it, перевод строки даёт разрыв строки), документы комплекта и формы — сервер (commonmark с таблицами GFM), условие упражнения — клиент (markdown-it, как задания). Правила, которые работают везде:

- Абзац — одна строка исходника. Между абзацами и перед списком пустая строка.
- Внутри нумерованного списка нет вложенных списков и блоков кода. Выносим их отдельным абзацем после списка.
- HTML не работает. Ссылки только абсолютные `https://`, относительные и `#якоря` превращаются в текст.
- В блоках кода строка не начинается с «#»: сервер примет её за заголовок раздела.
- Таблица — только для настоящих табличных данных: до трёх столбцов, короткие ячейки, в ячейке с кодом одно имя.
- Строки кода короче 60 знаков: на телефоне видно около 40.
- Заголовки «## » до 50 знаков: они попадают в оглавление.
- Условие упражнения — тоже Markdown. Код пишем в обратных кавычках. Пункты отмечаем «•» с одним переводом строки. Строка не начинается с «1. », «- » или «#». Длина условия до 1200 знаков: ученик читает его в узкой панели под редактором.

## Как править и проверять

1. Перед правкой копируем комплект целиком (`private/` не в Git, иначе «было» пропадёт): `.runtime/voice-backup-<дата>/<комплект>/`.
2. Один комплект за раз, сначала тексты ученика.
3. Сверка кода: все блоки кода, фрагменты в обратных кавычках, ссылки и строки таблиц из «было» должны остаться в «стало» без изменений.
4. Сканер маркеров: в тексте ученика нет канцелярита, оценок, «вы» и эмодзи; тире не больше 4 на 1000 знаков, жирных не больше 2 на 1000.
5. Читаем вслух. Если фразу так не сказать на занятии, переписываем. Каждый комплект ученика читает владелец.
6. Упражнения. Правка названия, условия, названия теста или комментария в заготовке меняет хеш, и без новой `revision` каталог не опубликуется. Правим источник условий (скрипт сборки комплекта или `training/catalog.json`), поднимаем `revision`, пересобираем и прогоняем проверку комплекта и тесты, которые ищут упражнение по названию. Назначение не закреплено за ревизией: ученик сразу видит новую, его черновик остаётся на старой, а сохранение и отправка дают конфликт ревизии, пока он не подтвердит переход. Текущая ревизия общая для пространства. Поэтому ревизию поднимаем, только когда по упражнению нет работы в процессе.
7. Кабинет. Правка файла его не меняет. Перепубликация занятий и публикация каталога только по команде владельца, после копии, по `docs/operations/java-angular.md`. Домашнюю работу, по которой есть непроверенная сдача, не перепубликуем.

## Пример

Было:

> Дубль id книги — `IllegalStateException`.
> В `returnBook` — сообщение вместо пустой строки.

Стало:

> Для дубля id книги бросай `IllegalStateException`, как уже сделано для читателя.
> В `returnBook` замени пустую строку в исключении на понятное сообщение.

«Как уже сделано для читателя» взято из ревью того же комплекта.
