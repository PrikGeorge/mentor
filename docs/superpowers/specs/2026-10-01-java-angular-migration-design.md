# Перенос кабинета наставника на Java и Angular

Дата: 1 октября 2026 года. Статус: подтверждена пользователем в чате 1 октября 2026 года.

## 1. Цель и согласованное направление

Переписать существующий сайт на Angular и Java/Spring Boot, сохранив рабочие учебные сценарии, данные и зелёно-песочный стиль. Платформа рассчитана на нескольких независимых преподавателей со своими учениками. Администраторы приглашают преподавателей по ссылке; преподаватели приглашают своих учеников.

Основание: обсуждение архитектуры в этом чате и просьба пользователя «давай перепишем на Java + angular». Пользователю знакомы Java/Spring Boot и Angular. Полные домашние проекты загружаются для ручной проверки. Тренажёр проверяет заранее подготовленные задачи с фиксированными зависимостями.

Успех — преподаватель и ученик проходят существующий учебный цикл в новой системе, их материалы и история сохранены, данные разных преподавателей изолированы. Замена технологий сама по себе не считается завершением.

## 2. Способ перехода

Выбран поэтапный перенос в этом репозитории: новую реализацию разрабатываем и проверяем рядом с текущей, на отдельном порту и отдельной тестовой базе. После полного переноса сценариев выполняем одно контролируемое переключение записей на новую систему.

Альтернативы: одновременная замена работающего приложения усложняет диагностику и откат; постоянное смешивание старых Node-маршрутов и новых Java-маршрутов создаёт два источника правил доступа. Временные адаптеры допустимы для проверки совместимости, но конечный сервер платформы и исполнитель проверки написаны на Java.

Текущие локальные данные и работающий сервер остаются источником истины до переключения. Двойной записи в JSON и PostgreSQL нет. Публикация в интернете и покупка ресурсов не входят в этот перенос.

Исходная реализация для переноса — текущая рабочая копия, включая изменённые и новые файлы, а не только последний Git-коммит. До реализации сохраняется проверенный снимок этой копии; игнорируемые данные, загрузки и необходимые локальные настройки резервируются отдельно и не публикуются в Git.

## 3. Целевая структура

- `frontend/`: Angular 22, TypeScript 6, RxJS 7, standalone-компоненты, Router и Reactive Forms. Node.js 24.15+ в пределах ветки 24 нужен для сборки и локальной разработки.
- `backend/`: Java 21, Spring Boot 4.1, Spring MVC, Spring Security, Spring Data JPA, Spring Session JDBC, Flyway и Maven Wrapper.
- `runner/`: отдельное Java-приложение, исполняющее задания проверки в Linux-контейнерах. Оно не входит в процесс веб-сервера.
- `infra/`: конфигурация локального запуска, контейнеров, HTTPS-прокси, резервного копирования и восстановления.
- PostgreSQL 17: данные платформы, сессии и долговечная очередь проверок.
- Закрытое хранилище файлов: локальный постоянный каталог в разработке; S3-совместимое хранилище для размещения. Оба варианта реализуют один интерфейс приложения.

Точные patch-версии зависимостей фиксируются в Maven BOM, Maven Wrapper и npm lockfile при реализации. Сборка использует совместимые версии из официальных матриц, без плавающих `latest`.

Бэкенд — одно развёртываемое приложение с модулями `identity`, `workspaces`, `students`, `lessons`, `materials`, `practice`, `homework`, `files`. Модули взаимодействуют через прикладные сервисы; контроллеры не обращаются к чужим репозиториям напрямую. Spring Modulith можно использовать для проверки этих границ, он не является условием работоспособности.

Браузер обращается к `/api/v1` на том же домене, откуда загружен Angular. HTTPS-прокси отдаёт статическую сборку и направляет API в Spring Boot. Исполнитель получает задания и отдаёт результаты через отдельный внутренний API бэкенда.

## 4. Аккаунты, преподаватели и границы доступа

Сущность `User` хранит глобальную учётную запись. `Workspace` принадлежит преподавателю, а `Membership` связывает аккаунт с пространством и ролью. `StudentProfile` хранит учебную карточку внутри пространства и может существовать до регистрации ученика.

Для первой версии один преподаватель владеет одним пространством, аккаунт ученика связан с одним пространством и одной карточкой. Одновременное обучение одного аккаунта у разных независимых преподавателей — отдельное расширение; текущий перенос не вводит этот сценарий. Это также оставляет однозначным право преподавателя восстановить доступ своего ученика.

- Администратор управляет приглашениями преподавателей, состоянием их аккаунтов и пространств. Административная роль сама по себе не открывает учебные материалы всех преподавателей.
- Преподаватель управляет учениками, занятиями, материалами, назначениями и ревью своего пространства. Просмотр кабинета ученика не даёт возможности отправить решение или ДЗ от его имени.
- Ученик читает доступные ему материалы, меняет собственные черновики, запускает проверки и отправляет собственные работы.

У студентов, занятий, материалов, упражнений, назначений, попыток, работ и файлов есть принадлежность пространству. Запросы фильтруются по ней на сервере. Связи проверяются составными ограничениями базы, где это необходимо: занятие не может ссылаться на ученика другого пространства. Переданный клиентом `workspaceId` не является доказательством доступа. Чужой идентификатор не раскрывает содержимое или существование частной записи.

Первый администратор создаётся локальной CLI-командой с интерактивным вводом пароля. Импорт существующего преподавателя сохраняет ему преподавательские права; глобальные административные права автоматически не добавляются.

## 5. Вход, приглашения и сессии

Сохраняем логины и парольную авторизацию. Пароль: 8–128 Unicode-символов и до 512 байт UTF-8, без обрезания пробелов; некорректные Unicode-последовательности отклоняются. Логины остаются нечувствительными к регистру с текущей нормализацией и ограничениями.

Новые пароли обрабатываются Spring Security SCrypt с параметрами не слабее текущих. В записи хранится идентификатор формата; совместимый адаптер читает импортированный JSON-формат. Параллельные вычисления хешей и очередь входов ограничены, чтобы не исчерпать память сервера.

Приглашения преподавателей создаёт администратор, приглашения учеников — их преподаватель. Ссылка действует 72 часа, используется один раз и хранится только как хеш токена. Активация приглашения и создание членства выполняются в одной транзакции, включая защиту от одновременного повторного использования. Новое приглашение на ту же карточку отзывает прежнее. Роль назначает сервер по приглашению.

Сессии хранятся в PostgreSQL. Cookie в production: `Secure`, `HttpOnly`, `SameSite=Lax`, область одного хоста. Все изменяющие запросы защищены CSRF; Angular guards служат навигации, а права проверяет Spring Security и прикладной сервис. Перезапуск бэкенда не завершает действующие сессии. Сохраняются текущие пределы: 8 часов бездействия и 7 суток общего срока.

Смена пароля отзывает остальные сессии; восстановление пароля отзывает все сессии. Одноразовые ссылки восстановления действуют 30 минут. Преподаватель подтверждает текущий пароль при выдаче такой ссылки своему ученику; администратор аналогично восстанавливает доступ преподавателю. Приостановка доступа немедленно запрещает запросы и отзывает сессии. Для первого администратора предусмотрено локальное восстановление через CLI.

Сохраняются ограничения частоты попыток входа и выдачи токенов. Пароли, токены ссылок, cookie и исходный код ученика не попадают в обычные журналы запросов.

## 6. Сценарии и интерфейс Angular

Разделы загружаются по маршрутам: администрирование, преподаватель, ученик. Общими остаются компоненты навигации, форм, материалов, Markdown-редактора, загрузки файлов и статусов. Signals используются для локального состояния интерфейса, HttpClient/RxJS — для запросов. Глобальное хранилище состояния вводится только при появлении конкретной потребности.

Обязательная совместимость поведения:

1. Карточки учеников: имя, направление, цель, расписание, маршрут и закрытые заметки преподавателя; создание и изменение карточки.
2. Занятия: короткая форма темы, даты, времени и длительности; подготовка после создания; отдельное редактирование сценария, заданий и общего отзыва.
3. Кабинет ученика: имя в верхней части меню, ближайшее/текущее занятие и переход к последнему при отсутствии будущих; задания, тренажёр, материалы, ДЗ и ревью внутри занятия; единая шапка.
4. Подготовленные документы: план, методичка, эталоны, исходные заготовки рядом с заданиями, скачиваемые комплекты, оглавление, переходы по разделам и печать/PDF через браузер.
5. Существующие страницы навыков, маршрута, проектов и другие подготовленные документы сохраняются с исходной аудиторией доступа. Их содержимое импортируется как материалы, без условия `student.id === 'michael'` в Angular.
6. Ревью привязано к занятию и конкретной сдаче. Старый общий `studentReview` остаётся отдельным архивом и не копируется в каждое занятие.
7. Предпросмотр преподавателем ученического кабинета остаётся явно обозначенным режимом чтения.

CSS-переменные цветов, типографика, отступы и знакомые элементы переносятся в общий набор стилей. Проверяются компьютер, ширина 390 px, управление клавиатурой и читаемость длинных материалов. Новое оформление страниц в задачу не входит.

Новые маршруты используют Angular Router. Адаптер прежних `#students/...` ссылок сохраняет ученика, занятие, раздел, якорь и режим просмотра, затем перенаправляет на соответствующий новый маршрут после проверки доступа.

## 7. Тексты, материалы и файлы

Исходный Markdown хранится в PostgreSQL как `TEXT`; пробелы, отступы, переносы и блоки кода не нормализуются при сохранении. Сценарий, задания и ревью имеют независимые ревизии, чтобы сохранение одного поля не перезаписывало другое. Конфликт редакций возвращает `409` и явный выбор пользователя.

Сохраняем импорт UTF-8 `.md`/`.markdown` с заменой или добавлением, undo/redo, панель форматирования и предпросмотр. Один текст занятия — до 200 000 UTF-16 единиц, импортируемый файл — до 1 МиБ. Импорт становится постоянным только после сохранения. Лимиты и ошибки API согласованы с интерфейсом; запрос сохранения текстов занятия допускает до 4 МиБ JSON.

Один Angular-сервис рендерит Markdown и в предпросмотре, и на странице. HTML исходника не исполняется, запрещённые схемы ссылок отбрасываются, внешние изображения автоматически не загружаются. Скомпилированные старые материалы импортируются из доверенных исходников с сохранением специальных блоков и разделения аудиторий; пользовательский ввод через этот путь не проходит.

Материал содержит владельца, аудиторию, привязку к ученику/занятию, тип и ревизию. Преподавательские заметки, эталоны и служебные файлы не включаются в ученические DTO, Angular assets и общедоступные комплекты скачивания.

Файлы имеют метаданные в базе и непрозрачный ключ хранилища. Загрузка потоковая, через multipart, с ограничением размера на прокси и сервере. Временный объект становится доступен после завершения загрузки и фиксации записи; незавершённые объекты очищаются. Скачивание в первой версии идёт через авторизованный API, без публичных bucket и постоянных внешних ссылок.

Полное ДЗ: ZIP, Java, TXT, Markdown или PDF до 20 МиБ, комментарий и необязательная HTTPS-ссылка на репозиторий. Каждая сдача самостоятельна; преподаватель видит историю и задаёт «Проверено» либо «Нужна доработка». Файлы проектов не распаковываются и не исполняются.

## 8. Тренажёр и исполнитель

Сохраняются Monaco с запасным текстовым редактором, несколько объявленных Java-файлов, запуск примеров, полная проверка, автосохранение черновика, история кода и результатов. При потере сессии или сети редактор удерживает локальную копию, привязанную к аккаунту и заданию; другой аккаунт её не получает. Конфликт сохранения и смена ревизии упражнения требуют явного выбора. Выход из аккаунта предлагает сохранение или экспорт, если отправить черновик не удалось. Ограничение общего размера исходников сохраняется: 256 КиБ UTF-8 на попытку.

Упражнение и его ревизия фиксируют условие, шаблоны, разрешённые файлы, проверяемый интерфейс, тесты и версию окружения. Попытка неизменно хранит соответствующие ревизии, снимок кода и итог проверки. Изменение каталога не меняет смысл старых попыток.

Готовые каталоги и профили окружений публикуются оператором через версионируемые файлы и команду импорта с явным пространством назначения. Преподаватель назначает доступные упражнения занятию как классные или домашние. Полноценный визуальный конструктор тестов и Maven-профилей не входит в этот перенос. Пользовательские определения не могут задавать произвольную команду оболочки, путь хоста или Docker-образ.

Окружения заранее собираются из разрешённых JDK и зависимостей с точными версиями и контрольными суммами; образы фиксируются digest. Первые профили сохраняют Java 21 и существующий пример Jackson. Сетевой доступ для подготовки зависимостей существует только в отдельном доверенном процессе сборки. Во время ученической проверки загрузок библиотек нет.

Поток проверки:

1. API проверяет права и ограничения кода, в одной транзакции сохраняет снимок попытки и задание очереди, возвращает `202` с идентификатором.
2. Исполнитель через внутренний API получает одно задание с арендой и уникальным токеном попытки исполнения. Захват в PostgreSQL транзакционный; у одной записи только одна действующая аренда. Heartbeat продлевает аренду в пределах жёсткого срока исполнения; потеря heartbeat запускает восстановление после её истечения.
3. Исполнитель запускает отдельный контейнер: без сети, секретов, Docker socket и файлов платформы; непривилегированный пользователь, read-only root, ограничения CPU, RAM, процессов, времени и вывода.
4. Результат принимается только по действующей аренде и фиксируется идемпотентно. Состояния очереди отделены от вердиктов тестов: `queued`, `running`, `completed`, `failed`.
5. Angular опрашивает состояние активной попытки с увеличением интервала при ошибках; перезагрузка страницы восстанавливает ожидание по идентификатору.

Прерванные инфраструктурой задания после истечения аренды допускают одну повторную попытку исполнения, затем получают инфраструктурную ошибку. Ошибка компиляции, неверный ответ и превышение времени не запускают автоматический повтор. Устаревший исполнитель не может перезаписать новый результат. Истёкшие контейнеры завершаются и очищаются; временный дубль после потери связи не считается повторной сдачей ученика. Перегрузка очереди возвращает понятную ошибку и сохраняет код в редакторе.

Веб-бэкенд не имеет доступа к Docker. Исполнитель получает только данные назначенной проверки, без прямых учётных данных основной БД и хранилища ДЗ. Его внутренний API закрыт от браузера и аутентифицирует отдельную служебную учётную запись. Для публичного размещения исполнитель находится на отдельной VM; Docker Compose на одном компьютере допускается для локальной разработки. При недоступной проверке кабинет продолжает работать и показывает явный статус.

## 9. API, ошибки и диагностика

Контракт REST описывается OpenAPI. Angular использует сгенерированные типы/клиент; ограничения проверяет сервер. Списки учеников, занятий, попыток и работ имеют пагинацию. Запись возвращает актуальную ревизию ресурса. Повторная отправка решения с тем же idempotency key не создаёт вторую попытку в пределах того же аккаунта и назначения.

Общие ошибки: `401` — нужен вход, `403` — действие запрещено, `404` — ресурс недоступен, `409` — конфликт версии, `413` — превышен размер, `429` — частые запросы/перегрузка, `503` — временно недоступна подсистема. Ответ содержит код, понятное сообщение, ошибки полей и идентификатор запроса, без stack trace.

При ошибке сохранения редактор удерживает введённый текст. При ошибке загрузки файла работа не показывается как успешно сданная. При сбое БД операции записи не получают успешный ответ. Диагностика отслеживает ошибки API, очередь, длительность проверок и состояние резервных копий; аудит фиксирует приглашения, блокировки и изменение прав.

## 10. Перенос существующих данных

Импорт выполняется отдельной CLI-командой на копии данных; режим dry-run только проверяет и строит отчёт. Источники: `data/mentoring.json`, `data/auth/accounts.json`, `data/practice/**`, подготовленные закрытые материалы, исходные документы и каталог `training/`. Рабочая копия не отправляется во внешние сервисы.

- Сохраняются внешние строковые идентификаторы, включая `michael`, `lesson-2026-09-27` и идентификаторы файлов. Новые записи получают UUID в строковом представлении; существующие ссылки продолжают разрешаться.
- Существующий преподаватель получает первое пространство. Все его ученики, занятия, материалы, упражнения и результаты относятся к этому пространству. У новых преподавателей пустые кабинеты; чужие комплекты автоматически не копируются.
- Даты/время занятий трактуются как локальные дата и время в `Europe/Moscow`. Хранятся локальные поля и зона; технические временные отметки — UTC. Импорт не сдвигает расписание.
- Хеши паролей импортируются с исходными параметрами scrypt (`N=131072`, `r=8`, `p=1`, соль 16 байт, ключ 64 байта). Java проверяет их совместимым адаптером; хеш не хешируется повторно вместо пароля. Совместимость подтверждается искусственными тестовыми векторами, включая Unicode и пробелы.
- Активные старые приглашения и ссылки сброса при переключении отзываются и при необходимости выдаются заново. Старые сессии не переносятся, после переключения требуется вход. Отозванные/использованные токены не становятся действующими.
- Сохраняются назначения, черновики, архивы ревизий, попытки, результаты, сдачи, комментарии и файлы. Если для старого подготовленного занятия назначений в JSON ещё нет, импорт воспроизводит фактически действовавшее ленивое назначение `list-task`/`grouping-task`; явно сохранённые пустые назначения не заменяются.
- До смены домена/порта несохранённые браузерные черновики сохраняются на старом сервере или экспортируются пользователем. Новый origin не может автоматически прочитать локальное восстановление старого. При сохранении origin адаптер восстановления проверяет владельца и версии; бесхозные старые записи не привязываются к текущему аккаунту автоматически.
- Изолированные или повреждённые связи и отсутствующие файлы попадают в отчёт и блокируют окончательный импорт; данные не отбрасываются молча. Для повторного запуска используются идентификатор импорта и контрольные суммы, исключающие дубликаты.

Отчёт сверяет количества по сущностям, связи, тексты и контрольные суммы файлов. Скопированные бинарные объекты проверяются до финальной фиксации миграции; незавершённая попытка импорта не считается готовой системой.

Переключение: резервная копия → остановка записей старого приложения → финальный импорт → проверки → открытие новой системы. До открытия записей откат возвращает старую копию. После появления новых записей автоматический откат на старые JSON запрещён: сначала сохраняются новые изменения и готовится явный обратный перенос, иначе они будут потеряны.

## 11. Этапы и критерии готовности

Этап 1 — основа и доступ: схема PostgreSQL, Flyway, модули, вход, администратор, приглашения преподавателей/учеников, пространство владельца, тестовый импорт. Готовность: два преподавателя и два ученика проходят вход; прямые запросы и скачивания между пространствами запрещены; существующий пароль работает после импорта.

Этап 2 — учебный кабинет: Angular-навигация, карточки, занятия, подготовленные материалы, Markdown-редактор, ревью и загрузка ДЗ. Готовность: сохраняются текущие сценарии и лимиты, работают старые ссылки, новый ученик не получает комплект другого, Markdown и файлы совпадают с источником.

Этап 3 — тренажёр: импорт упражнений и архивов, Java-исполнитель, долговечная очередь, редактор и история. Готовность: обе исходные задачи и задача с Jackson проверяются; неверное решение, компиляция, зависание и чрезмерный вывод дают корректный результат; перезапуск компонентов не теряет принятую попытку.

Этап 4 — приёмка и переход: полный тестовый импорт, сквозные сценарии и визуальная проверка, запуск локально на Windows, конфигурация Linux-хостинга, резервная копия и проверенное восстановление. Старый сервер выводится из использования только после успешной проверки сохранности и переключения.

Тесты: JUnit и интеграционные проверки с PostgreSQL/Testcontainers для транзакций, приглашений, прав и очереди; Angular-тесты поведения форм и редакторов; браузерные проверки основного пути преподавателя/ученика. Дополнительно проверяются закрытые поля в фактических ответах API, повторные запросы, конфликт черновика, отзыв доступа и исчерпание лимитов исполнителя. Требуется прогон восстановления базы и файлов из согласованной резервной копии.

Систему можно считать перенесённой, когда все четыре этапа завершены, текущие данные сверены, нет пропавших пользовательских сценариев, а production-запуск не зависит от Node.js-сервера или Python-компилятора материалов. Подготовленная Angular-сборка и материалы отдаются новой системой.

## 12. Основания для технических решений

- [Требования Spring Boot](https://docs.spring.io/spring-boot/system-requirements.html): Java 21 совместима с выбранной веткой Spring Boot 4.1.
- [Совместимость Angular](https://angular.dev/reference/versions): Angular 22 требует совместимых Node.js, TypeScript и RxJS; версии инструментов сборки закрепляются вместе.
- [Spring Session JDBC](https://docs.spring.io/spring-session/reference/configuration/jdbc.html): хранение серверных сессий в реляционной БД.
- Текущие сценарии и ограничения: `README.md`, `lib/auth-passwords.cjs`, `lib/access-policy.cjs`, `lib/store.cjs`, `lib/practice-api.cjs`, `lib/practice-store.cjs`, `lib/materials-api.cjs`, `lib/java-runner.cjs` и существующие спецификации авторизации/тренажёра.

При расхождении старых спецификаций с выполненными доработками источником функционального соответствия являются текущие обработчики, README и более поздние пожелания пользователя: прежний документ тренажёра, например, описывает состояние до внедрения авторизации.

Этот документ фиксирует проект и критерии приёмки. Детальная последовательность изменений файлов и команд проверки оформляется в плане реализации после согласования спецификации.
