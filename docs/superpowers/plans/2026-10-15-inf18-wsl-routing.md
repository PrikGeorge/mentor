# INF-18 — выбор WSL и преобразование путей

Владелец INF, смежные B/INF и QA; база `296ae65`, отдельный коммит без push. Q-18 на реальном снимке ждёт разрешённого пути и SHA256, его инструмент уже принят.

- [x] Один selector `MENTOR_WSL_DISTRIBUTION`; без значения — default WSL, без fallback при ошибке. Не читать настройки из рабочего compose.env.
- [x] Docker, stdin, GnuPG и долгоживущее соединение backup fence используют selector; команды передаются аргументами, без shell-склейки.
- [x] Windows-пути конвертируются через wslpath выбранного дистрибутива, с проверкой кода выхода/единственной строки/абсолютного пути; Linux-ветка остаётся прямой.
- [x] Новые поведенческие mock-тесты: default/явный distro, иной mount root, пробелы/Unicode/литеральные спецсимволы, ошибки, stdin и ProcessStartInfo. Приспособить прежние двойники, не обращаться к реальному Docker.
- [x] Проверки инфраструктуры, смежное ревью, документация/AGENTS/строка §0, локальный коммит.

Локальная read-only проверка wslpath: несуществующий синтетический путь с пробелами, кириллицей, `$` и апострофом проходит Windows→WSL→Windows без изменения. Рабочие конфиги/данные и Docker-проект не открываются; scheduled tasks не изменяются.

Проверки: RED — выбранный synthetic distro игнорировался; после правки mock-набор проходит. Все 11 Windows mock-сценариев из CI прошли отдельными процессами на NTFS; парсер — 41 PowerShell-файл. Реальный `backup-fence.ps1` прошёл с явно выбранной Ubuntu на собственной PostgreSQL (`--network none`, tmpfs, удаление только своего container ID); проверены экспортированный snapshot, взаимное исключение, потеря соединения и снятие блокировки. Read-only roundtrip несуществующего синтетического пути через настоящий wslpath прошёл.

CI исправлен по QA-ревью: реальный backup-fence исключён из Windows mock-job; каждый mock-сценарий запускается отдельным pwsh-процессом, чтобы ожидаемые отрицательные exit codes и функции-двойники не переходили в следующий тест. Тест ярлыка требует NTFS junction; FAT32-падение устранено запуском из NTFS-копии, assertions не ослаблялись. Тест scheduler дополнен wslpath-double: ошибка Docker по-прежнему возникает на своей проверяемой границе.

Приложение/API/схема БД не менялись: используются предыдущие результаты Q-18 (backend 209), FE-11 (unit 306), FE-12 (UI 31, real 12), FE-05 (build/schema). Реальный Q-18, runner daemon и practice fixture остаются открытыми. Рабочий контур и Task Scheduler не изменялись.
