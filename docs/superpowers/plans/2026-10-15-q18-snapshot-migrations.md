# Q-18 — проверка миграций на снимке

Владелец QA; смежные ревью B и INF. База `e00b628`, одна задача/локальный коммит без push.

- [x] Тестовый CLI с явными dump/SHA256/report, без подключения к существующей БД и без поиска копий.
- [x] Новый PostgreSQL на каждый запуск: собственная bridge-сеть, loopback port, копирование dump без bind mounts, закрытие только собственных ресурсов.
- [x] Проверка Flyway history/checksums, сохранения counts прежних таблиц, выполнения новых миграций и повторного запуска без изменений.
- [x] Синтетическая заполненная V14 → pg_dump → новая БД → V15, данные/индексы; fail-fast для неверного ввода.
- [x] Backend verify, смежное B/INF/QA-ревью, документация и карта, строка раздела 0 и локальный коммит.
- [x] Инструмент готов; по решению владельца от 15.10.2026 реальный прогон выполняет владелец при следующем релизе из свежей копии и `manifest.databaseSha256`. Агенту доступ к настоящим копиям не выдаётся. Точная команда и ожидаемый результат добавлены в шаг релиза «Q-18: smoke миграций на снимке»; это обязательная проверка релиза, а не незавершённая задача разработки.

Граница данных из раздела 0.1 бэклога: рабочие конфиги, реальные данные и копии не читаются без отдельного указания. Код и проверки инструмента выполняются на синтетике; использование настоящего снимка — отдельный незакрытый gate. Инструмент не запускает Spring, blob cleanup или исполнителя и не проверяет содержимое файлового хранилища.

Проверка среды: Docker Desktop не публикует JDBC-порт контейнера с `internal=true` (`NetworkSettings.Ports={}`); этот вариант отклонён до копирования dump. Выбрана собственная обычная bridge-сеть с проверкой единственного подключения и порта на 127.0.0.1. Она не ограничивает исходящий трафик, инструмент предназначен только для доверенного снимка.

Целевой прогон на NTFS — 9/9, без ошибок и пропусков. По B/INF/QA-ревью добавлены отказы для актуального dump/неверного Flyway checksum, повторная проверка содержимого после второго migrate, безопасные коды отказа и проверки реального CLI subprocess (JSON, отсутствие приватных значений/путей в выводе, сохранность существующего отчёта). Уточнён SHA256 именно `database.dump` из `manifest.databaseSha256`. Полный backend verify на NTFS — 209/209, 0 ошибок и пропусков, BUILD SUCCESS (5:37); все 185 файлов backend/src совпадают с рабочей копией. Frontend, API, production Java и миграции не менялись; их релевантные прежние проверки — FE-11/FE-12/FE-05. Общие gates runner daemon и practice fixture остаются открытыми, выпуска в рабочий контур не было.
