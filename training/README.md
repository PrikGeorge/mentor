# Каталог учебных проверок

Эти файлы принадлежат преподавателю и находятся вне `dist`. Браузер получает только ID, версию, условие, исходные заготовки и публичное описание окружения. Проверки, Java-мост и настройки запуска через каталог API не выдаются. Это локальный кабинет: ученический режим отображения сам по себе не создаёт авторизацию.

## Подготовка

Из корня проекта:

```powershell
node scripts/prepare-training.cjs
docker pull eclipse-temurin:21-jdk-jammy
node --test test/training-runner.test.cjs
```

Подготовка загружает только перечисленные в `environments.json` JAR из Maven Central по HTTPS. Каждый артефакт проверяется по закреплённому SHA-256; список транзитивных зависимостей указывается явно. Maven, Gradle, POM и команды ученика не исполняются. Во время попытки нет загрузки или автоматического разрешения зависимостей. Путь кеша по умолчанию `.runtime/training-cache`; для другого места используйте `--cache-dir PATH` и такой же `cacheDir` при создании runner. Параметр `--profile java21-jackson` подготавливает только выбранное окружение.

Профиль `java21-jackson` содержит `com.fasterxml.jackson.core:jackson-databind:2.18.3` и ровно две явно разрешённые транзитивные зависимости: `com.fasterxml.jackson.core:jackson-core:2.18.3`, `com.fasterxml.jackson.core:jackson-annotations:2.18.3`. Других библиотек в classpath нет. SHA-256 каждого JAR сохранён в `environments.json`. Это зафиксированное учебное окружение; обновление библиотек выполняет преподаватель вместе с перепроверкой задач. Пример `json-task` использует Jackson и два Java-файла в пакете `demo`; он не назначается ученикам автоматически.

## Режимы выполнения

`MENTOR_JAVA_MODE=auto` — значение по умолчанию. Runner предпочитает готовый Docker с Linux и Java 21. Если он недоступен, локальный режим разработки возможен только с `java` **и** `javac` версии 21 в `PATH`. `JAVA_HOME` без корректного `PATH` не выбирает другую Java.

- `MENTOR_JAVA_MODE=docker` требует Docker и подготовленный образ, без перехода к локальному запуску.
- `MENTOR_JAVA_MODE=local` явно выбирает ограниченный локальный JDK 21.
- `MENTOR_JAVA_MODE=disabled` отключает исполнение.
- При `NODE_ENV=production` локальное исполнение запрещено, включая fallback из `auto`. Для публичного сервера используйте обязательный Docker; аутентификация и сетевой доступ требуют отдельной реализации.

Статус точно сообщает текущий режим. Проверка недоступности возвращает `unavailable`, а не успешный результат. Статус окружения кешируется на срок жизни runner; после подготовки/смены JDK или Docker перезапустите сервер.

Docker запускается без сети, от UID/GID 10001, без capabilities, с `no-new-privileges`, read-only корнем, лимитом 512 МиБ, одним CPU и 128 процессами. В контейнер монтируется только отдельный временный каталог данной попытки с исходниками, разрешёнными JAR и доверенным мостом — никаких данных кабинета. Запись компилятора идёт в ограниченный tmpfs. После проверки контейнер удаляется; у него также есть самостоятельный 90-секундный срок жизни на случай остановки сервера.

В обоих режимах доверенный Java-мост и ученические классы имеют разные загрузчики и protection domain. Java 21 SecurityManager policy даёт права только мосту; ученик не получает доступ к файлам, сети, процессам, native-библиотекам, управлению потоками или снятию policy. `main` ученика не вызывается. Локальные Java policy и ограничения ресурсов **не являются системной песочницей** и предназначены только для разработки на этом компьютере. Исполнение произвольного кода на хостинге требует контейнерной границы и отдельной эксплуатационной настройки.

Ограничения: 16 объявленных исходных файлов, 128 КиБ на файл и 256 КиБ суммарно; очередь до 4 попыток с последовательным выполнением; компиляция до 15 секунд; один тест до 3 секунд; весь этап проверки до 45 секунд; JVM решения 128 МиБ heap; пользовательский вывод до 16 КиБ на тест. Лимит очереди включает выполняющуюся попытку. Процессы имеют отдельный общий лимит вывода. Зависание, превышение вывода, аварийное завершение или незавершённый протокол никогда не дают `accepted`.

## Добавление упражнения

1. Добавьте каталог `exercises/<id>/` и Java-заготовки. Список файлов фиксирован: ученик может менять их содержание, но не добавлять пути, build-файлы или зависимости. Java-пакеты поддерживаются (`demo/JsonTask.java`).
2. Добавьте запись в `catalog.json`: уникальный `id`, целочисленный `revision`, русские `title`/`statement`, `environmentId`, массив `starterFiles` с относительными путями.
3. Укажите `className`, `method`, `parameterTypes` — точные имена стираемых типов для поиска метода (`java.util.List`, `int`, `java.lang.String`). Методы и конструкторы могут быть package-private; нестатическому методу нужен конструктор без аргументов.
4. В `tests` укажите `name`, JSON-массив `args`, JSON-значение `expected`. Хотя бы один пример имеет `sample:true`: кнопка «Запустить» проверяет только такие случаи, «Отправить» — весь набор. `unchangedArguments:[0]` проверяет значение аргумента до и после вызова, включая поля объявленных пользовательских объектов.
5. Для пользовательского типа задайте `customTypes`: ключ — полное бинарное имя (`GroupingTask$Loan`), `constructorTypes` — типы параметров конструктора, `fields` — поля в порядке соответствующих параметров. JSON-аргумент объекта использует эти имена. Поля также входят в снимок проверки мутаций. Поддержаны primitives/boxed values, строки, массивы, generic List/Set/Map и объявленные пользовательские типы; для другого протокола расширьте доверенный мост и его тесты.
6. Укажите все зависимости в профиле с версиями и SHA-256, подготовьте кеш и проверьте правильное и неправильное решение. Если задан `annotationProcessors`, разрешены только указанные преподавателем полные имена из подготовленных JAR. Они запускаются только в Docker; локальный режим такого профиля возвращает `unavailable`. При пустом списке используется `-proc:none`. Ученический POM не используется.
7. Повышайте `revision` при изменении контракта, тестов, заготовки или окружения. Затем назначьте упражнение конкретному занятию через интерфейс преподавателя. Новые ученики и занятия не наследуют каталог автоматически.

## Проверка реализации

`node --test test/training-runner.test.cjs` выполняет реальные `javac`/`java`: правильные и ошибочные ListTask/GroupingTask, мутации, ложный stdout, ошибки компиляции, зависание, лишний вывод, запреты policy, границы очереди, Jackson и Docker. Если Docker отсутствует, соответствующий тест явно пропускается; для обязательной проверки установите `TRAINING_REQUIRE_DOCKER=1`. Проверка Jackson требует предварительно подготовленного кеша; отсутствие кеша в основном runtime проверяется отдельно и возвращает `unavailable`.

Мост использует идеи отдельного доверенного домена и JSON/reflection-адаптера из локального проекта `algocode-local` (`server.py`, `Harness.java`); его компактный JSON reader/writer перенесён в `TrustedHarness.java`. Оригинальный проект не менялся. Здесь добавлены поддержка package-private методов, объявленных объектов Loan, проверка мутаций и отдельный доверенный протокол завершения.
