# Кабинет наставника

Учебная платформа на Java 21 / Spring Boot 4 и Angular 22. PostgreSQL хранит пользователей, занятия, черновики и историю проверок; файлы выдаются из закрытого хранилища после проверки доступа. Java-исполнитель проверяет назначенные упражнения в отдельных Docker-контейнерах.

## Запуск

После подготовки конфигурации и готовых образов откройте `Start-Mentor.cmd`. Повторный запуск открывает тот же кабинет. На Windows нужны PowerShell 7.2+, Docker Desktop с Linux engine и доступом из WSL Ubuntu. Node.js и Python для запуска собранной платформы не нужны.

Настройки по умолчанию: `.runtime/platform/compose.env`. Они создаются при первоначальной подготовке, содержат пути к приватным secrets и не входят в Git. Адрес кабинета берётся из этих настроек. Для другого контура:

```powershell
./start-local.ps1 -NoBrowser -EnvironmentFile C:/MentorPrivate/platform/compose.env
```

[Подготовка, запуск, администрирование и резервные копии](docs/operations/java-angular.md). Запуск не импортирует старые JSON автоматически. Перенос старого кабинета выполняется отдельно, с закрытым снимком и проверенными зашифрованными копиями.

## Доступ и работа

Первого администратора создают интерактивной командой `admin` из backend JAR/контейнера. Пароль вводится скрыто. Администратор приглашает преподавателей; преподаватель создаёт карточки своих учеников и приглашает их по одноразовым ссылкам. Открытой регистрации нет. Пароль — от 8 символов; пробелы сохраняются.

Преподаватель видит только своё пространство, ученик — свою карточку и публичные материалы. Администратор управляет доступами, но не получает учебные материалы чужих пространств. Просмотр кабинета ученика преподавателем работает только для чтения.

- Новое занятие: тема, дата, время по Москве и длительность. Сценарий и задания заполняются после создания.
- Тексты занятия: Markdown, импорт `.md`, панель форматирования и предпросмотр. До 200 000 символов UTF-16 на текст; файл импорта — до 1 МиБ.
- Тренажёр: условие рядом с кодом, запуск примеров, полная проверка и история попыток. Изменение задания или конфликт сохранения не заменяют код молча.
- Домашняя работа: загрузка файла до 20 МиБ, комментарий и история сдач. Преподаватель оставляет отзыв к работе внутри занятия. Полные проекты автоматически не выполняются.
- Материалы: защищённое чтение и скачивание, код и печатная версия. Закрытые сценарии и эталоны не входят в публичную Angular-сборку.

При сбое связи несохранённый код остаётся в редакторе. Перед выходом можно сохранить, экспортировать, отменить выход или явно отказаться от изменений. Если исполнитель временно недоступен, кабинет продолжает работать, а проверка остаётся в очереди.

## Разработка

Каталоги: `backend/` — HTTP API и правила доступа; `frontend/` — Angular; `runner/` — исполнитель Java; `contracts/` — OpenAPI; `infra/` — образы, запуск и обслуживание.

Для сборки нужны JDK 21 и Node.js 24.15+ в пределах ветки 24. Maven Wrapper закреплён в репозитории. Установка Angular-зависимостей выполняется через `npm ci --prefix frontend`. Команды проверок и сборки описаны в [инструкции](docs/operations/java-angular.md).

Обычные браузерные проверки используют отдельные PostgreSQL/Spring-контуры с синтетическими данными. Проверка реального Java-исполнителя запускается отдельно. Рабочий порт 4173 и рабочие учётные записи в acceptance-тестах не используются.

### Проверки миграции — 1 октября 2026

- Backend: `mvnw.cmd -pl backend verify` — 161 тест, без ошибок и пропусков. Исполнитель отдельно проверен в Linux: 24 теста, без ошибок и пропусков.
- Angular: 185 тестов, production build; генерация типов API не меняет сохранённую схему.
- Браузер: реальные регистрация, занятия, Markdown, сдачи и ревью; разделение преподавателей/учеников/администратора и параллельные приглашения/сдачи. Импортированные профили и материалы проверены на ширине 1280 и 390 пикселей.
- Итоговые образы Angular/Caddy, backend и контейнер исполнителя проверены вместе на восстановленной PostgreSQL: List, Grouping и Jackson, неверное решение, история и перезагрузка; обе ширины прошли без ошибок страницы/консоли. Закрытые пути недоступны через публичный сервер.
- Зашифрованная копия импортированных данных восстановлена с совпадением записей и файлов; проверены вход и скачивание. Семь сценариев скрипта переноса включают сбой, продолжение и повтор без дублирования.

Исходный локальный кабинет переключён 1 октября 2026 года: полный импорт выполнен через Windows-скрипт и WSL/Docker, исходные логины и хеши паролей сохранены. Перенесены 2 ученика, 2 занятия, 31 материал, 8 файловых объектов, 3 попытки, 1 черновик и 1 сдача домашней работы. Зашифрованная копия новой базы и файлов проверена восстановлением в отдельный контур. Рабочий адрес — `http://127.0.0.1:4173/`.

На рабочем адресе проверены готовность API, точное совпадение принятой сборки и закрытие приватных путей. Вход с реальными паролями выполняет владелец: пароли не сбрасывались, их сохранность проверена по точному совпадению исходного материала хеширования. Полные сценарии входа и работы проверены ранее на отдельном контуре. Настройка внешнего хостинга и настоящего внешнего хранилища копий в эти проверки не входит.

## Данные и переход

Рабочие данные находятся в PostgreSQL и приватном хранилище объектов; резервная копия включает оба. Скрипты проверяют согласованность, шифрование и восстановление. Копии, secrets, исходные снимки и локальные настройки исключены из Git. Настройка внешнего хостинга, выгрузки копий и расписания выполняется оператором по инструкции.

Старый Node-сервер остановлен; исходные JSON и закрытый снимок сохранены для сравнения и восстановления. Прежняя инструкция находится в [архиве](docs/legacy/README-node.md). После появления новых записей в новой системе возвращаться к старым JSON без отдельного обратного переноса нельзя.
